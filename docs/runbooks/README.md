## 阅读顺序

1. 三人先读 [COMMON.md](COMMON.md)，采用同一套目录、运行编号和 Git 工作流。
2. A 阅读 [ROLE_A.md](ROLE_A.md)：基础设施、集群验收、版本冻结、合并与最终整合。
3. B 阅读 [ROLE_B.md](ROLE_B.md)：实验程序、检查器、数据准备、工作负载与原始历史。
4. C 阅读 [ROLE_C.md](ROLE_C.md)：run_id、故障执行、证据收集、分析与复现。
5. 三人一起确认 [REPO_CHECK.md](REPO_CHECK.md) 中的正式运行前检查项。

从现在起，C 统一创建并维护 run_id。本套职责分工优先于旧手册中“B 分配 run_id”的表述。原有数据不改名、不移动，在新登记表中记录旧路径即可。

## 下一次小组协同只做什么

1. A 提供当前 commit，三节点恢复健康。本轮以正式实验证据为重点，旧烟测/演练截图不作为阻塞项；报告若引用它们再补齐来源或新做一轮留证。
2. B 审查并补齐现有 runner/检查器，先做一个模型的小样本，不直接开始大矩阵。
3. C 建立 run-registry，收集三人对证据路径和运行步骤的确认。
4. 三人一起完成一次“正常基线”小样本，再完成一次“分区→验证→工作负载→恢复→备份”闭环。
5. A/B/C 各自通过分支和 PR 上传自己的产物，完成交叉审阅后才扩大采样。
